# Semantic Graph Research

Корпус исследования: **доказательное восстановление семантики существующей системы**
(Core Backend + Taxi Web) и выработка минимального языка семантически-фреймового графа,
достаточного для её описания.

Репозиторий — это **исследовательский архив, а не спецификация к реализации**.
Значительная часть документов имеет статус `PROVISIONAL`; открытые вопросы зафиксированы
явно и намеренно не закрыты.

## 1. Что здесь лежит

Корпус состоит из четырёх слоёв. Они читаются в разном порядке и решают разные задачи.

| Каталог | Слой | Что это |
|---|---|---|
| [`methodology/`](methodology/) | Нормативный | Как вести исследование: протоструктуры, цепочка `SOURCE → … → DECISION`, правила provenance и статусов. Определяет форму всего остального. |
| [`mcr/`](mcr/) | Язык | Model Change Records — эксперименты над самим языком графа. Каждый MCR: вопрос → эксперимент → результат → (не)изменение языка. |
| [`research-passes/`](research-passes/) | Факты | RP-01…RP-37 — проходы по реальному коду. Восстановление authentication, authorization, ролевой модели, location-пайплайна с привязкой к исходникам. |
| [`experiments/`](experiments/) | Проверки | Кристаллизации, rule scans, prevalence check, историческая реконструкция — разовые проверки гипотез, не входящие в нумерованные цепочки. |
| [`current-research-summary.md`](current-research-summary.md) | Итог | Текущее кумулятивное состояние исследования. **Точка входа, если читаете корпус впервые.** |
| [`research-summary.md`](research-summary.md) | История | Резюме ранней стадии: что было установлено, что осталось открытым. `STATUS: HISTORICAL`. |
| [`source-docx/`](source-docx/) | Исходники | Оригиналы в `.docx`, из которых выросла часть методологии. Не редактируются. |

Полный реестр всех документов — со статусами, версиями и соответствием исходным именам
файлов — в [`INDEX.md`](INDEX.md).

## 3. Словарь статусов

Нормативное разделение — [`research-methodology-v2.3.md`, раздел 9.1](methodology/research-methodology-v2.3.md):
существует три независимых набора статусов, и смешивать их нельзя.

```text
Claim Confidence    CONFIRMED / INFERRED / UNKNOWN
Research Result     CONFIRMED / REJECTED / SOURCE_GAP
Document Status     PROVISIONAL / COMPLETED / RECONCILIATION / HISTORICAL
```

Ниже — словарь значений, фактически встречающихся в шапках документов корпуса. Часть из
них смешивает уровни: корпус собирался до введения раздела 9.1, ретроспективная
нормализация старых проходов в этот cleanup не входила.

| Статус | Значение |
|---|---|
| `CONFIRMED` | Установлено по исходному коду, воспроизводимо. |
| `EVIDENCE-GROUNDED` | Опирается на конкретный источник, но вывод ещё не перепроверен независимо. |
| `PROVISIONAL` | Рабочая версия, может быть пересмотрена следующим проходом. |
| `PARTIALLY ANSWERED` | Исследовательский вопрос закрыт частично. |
| `SOURCE-GAP` / `SOURCE_GAP CONFIRMED` | Ответа нет, потому что нет исходника — и это установленный факт, а не пробел в работе. |
| `CONFIRMED NEGATIVE` | Проверено, что явления **нет**. Полноценный результат. |
| `RECONCILIATION` | Проход сводит расхождения между предыдущими версиями. |

## 4. Соглашение об именах

Это то, что нужно генератору документов (боту), чтобы новые файлы попадали на место сами.

```
methodology/     <slug>-v<MAJOR>.<MINOR>.md
mcr/             mcr-<NN>-<slug>.md
research-passes/ rp-<NN>-<slug>[-v<MAJOR>.<MINOR>].md
experiments/     <slug>[-v<MAJOR>.<MINOR>].md
```

Правила:

- **Только** `[a-z0-9.-]`. Никаких пробелов, кириллицы, скобок и заглавных букв.
- `<NN>` — двузначный номер прохода с ведущим нулём, из заголовка `# … Research Pass NN`.
- `<slug>` — из подзаголовка документа (вторая строка `#`), в kebab-case.
- Версия в имени файла берётся из подзаголовка (`… Trace v0.2` → `-v0.2`), а не выдумывается.
- **Запрещены суффиксы `(2)`, `-1`, `_1`, ` copy`.** Новая версия того же прохода — это
  новый номер версии в имени, а не «файл рядом». В исходном корпусе именно это правило и
  нарушалось: свежайшая версия RP-37 (`v0.4, CONFIRMED`) лежала в файле с суффиксом `(2)`,
  а по имени выглядела как случайный дубликат.
- Номер прохода **не переиспользуется** для другой темы. Сейчас под RP-02 лежат два разных
  исследования (`authentication` и `taxiweb-core-backend-mapping`) — это уже нарушение,
  оставлено как есть, чтобы не ломать перекрёстные ссылки внутри документов.

### Предложение: машиночитаемая шапка

Корпус про семантический граф, но сам не является графом: статус и связи лежат в прозе.
Если бот будет добавлять YAML-frontmatter, реестр можно собирать автоматически:

```yaml
---
id: rp-37
version: "0.4"
status: CONFIRMED
supersedes: rp-37-authentication-credential-value-flow-v0.3
sources: [taxi-master.zip, archive_17012026_1259_clear.zip]
---
```

Ретроспективно к 63 документам это не применялось — только предложение на будущее.

## 5. Особенности корпуса, о которых стоит знать заранее

- **Версии лежат рядом, не в архиве.** У RP-01, RP-05, RP-37 и `prototype-structures`
  сохранены все ревизии. Какая свежая — смотрите в [`INDEX.md`](INDEX.md), колонка «Версия».
- **Два тяжёлых файла.** `rp-08` и `rp-09` весят по ~1.2 МБ: внутри сырые дампы
  `taxi/cache/data.json` одной строкой на 400К символов. Формально это provenance,
  практически — читать их в браузере GitHub бесполезно.
- **Цитаты из прода санитизированы.** RP-33, RP-35, RP-37 цитируют фронтенд такси вместе
  с API-ключом картографического сервиса. Репозиторий публичный, поэтому значение ключа
  заменено на `<REDACTED>` с пометкой `[REDACTED DURING PUBLIC REPOSITORY SANITIZATION]`;
  имя файла, номера строк и остальной verbatim-контекст цитаты сохранены. Credential
  принадлежит владельцу исходной системы — ротация/отзыв выполняются на его стороне.
- **MCR-06 отсутствует.** Пропуск в нумерации есть в исходном корпусе; документ либо не
  создавался, либо не передан.
- **Исходные имена файлов сохранены** в [`INDEX.md`](INDEX.md) — сверка с тем, что
  выгружает генератор, возможна в любой момент.

исследованиями с тех пор не дополнялся. Добавленные файлы — `README.md`, `INDEX.md`,

`research-methodology-v2.3`, пометка `research-summary.md` как `HISTORICAL`. Новая версия
методологии при этом не создавалась: текущая остаётся **v2.3**.

Открытые вопросы исследования (`H-D`, `OQ-001`, `OQ-002`, незавершённая ветка `R-2`)
перечислены в [`research-summary.md`](research-summary.md), раздел 5.
